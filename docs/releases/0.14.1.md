# Roman War 0.14.1 — latest macOS standard

The September 26 audited campaign and Alpine route are now the approved Mac
release baseline. This promotes the tested gameplay from
`0.14.1-preview.20260926`, with production app identities and version metadata.

## Downloads

- [Roman War — full campaign, universal Mac ZIP](https://github.com/zhynek/Roman-War/releases/download/v0.14.1/Roman-War-macOS-0.14.1.zip)
- [Roman War Alpine Route — companion app, universal Mac ZIP](https://github.com/zhynek/Roman-War/releases/download/v0.14.1/Roman-War-Alpine-Route-macOS-0.14.1.zip)

Unzip and open the app, or drag it into Applications. No Godot installation or
server is required. Both packages contain Apple Silicon and Intel executables.
Execution was tested on Apple M3 Max; Intel hardware remains untested. Apps are
ad-hoc signed, not Developer ID notarized. If macOS blocks a downloaded copy,
use System Settings → Privacy & Security → Open Anyway for that app.

## Included changes

- Procedural terrain, muted roads, bridges, marsh causeways, passes, settlements
  and troop formations, with the classic map still available for comparison.
- Real deterministic forest concealment and paid patrols. Hidden enemy rosters
  remain private; presentation never advances campaign state or RNG.
- The playable Alpine route through Pannonia, Illyria, Venetia, Noricum and
  Raetia, packaged separately from the full campaign.
- Structural save validation, verified temporary writes, previous-good backups
  and recovery when the primary save is missing or structurally invalid.
- Stale tooltips cleared when the camera moves.
- Repeatable Mac packaging with exact source provenance, native version checks,
  universal architecture checks and packaged campaign/save probes.
- A [release audit](../reviews/2026-09-26-release-audit.md) and
  [prioritized development roadmap](../ROADMAP.md).

## Save locations and play

**Roman War.app** retains bundle ID `com.romanwar.game` and the existing
production slot at
`~/Library/Application Support/Godot/app_userdata/Roman War/roman_war_save.json`.
Older additive version-2 saves are supported. A subsequent successful Save keeps
the previous valid file in `roman_war_save.json.bak`.

**Roman War Alpine Route.app** uses bundle ID `com.romanwar.alpine-route` and
`~/Library/Application Support/Roman War Alpine Route/roman_war_save.json`.
It does not share the campaign slot. Previous preview/development saves remain
in their original folders; none are moved automatically.

For comparable campaign feedback choose **Julii, Medium, seed 42**, guided mode
on. Save through the campaign header. To continue after reopening, begin a
campaign and use **Load**. For the route, choose each waypoint in Alpine Frontier,
review the quote and issue orders; end turns to replenish movement and use
Patrol woods at Noricum. Include version, mode, seed, turn and province in reports.

## Verification and remaining limits

The audited gameplay passed 536 tests, data validation, real map/route rendering,
and packaged Save → quit → Load with identical state. Release packages are
rebuilt from the committed 0.14.1 source and checked again for data/import/export
errors, native signatures, architecture slices, package completeness and rendered
entry/play. Checksums and `BUILD-INFO.json` accompany the GitHub downloads.

Battles still auto-resolve; player-controlled tactical combat is roadmap work.
Naval warfare, AI/player action parity, clearer victory goals and broader art,
audio and interface polish remain priorities. One inherited UI anchor warning
remains. A historical GitHub timing gate failed at 603 ms versus its fixed
600 ms limit; remote CI status is reported separately from local verification.

Backup recovery uses the normal Load message and is not a promise of exhaustive
semantic validation or power-loss durability. The approved visual direction
remains original procedural art; this release is not a claim of finished
photorealism or full Rome: Total War feature parity.
